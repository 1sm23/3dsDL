# Localization

The offline catalog in `romfs/i18n.json` contains English, Simplified Chinese,
Spanish, French, Portuguese, German and Japanese. The Receive web page follows
the language selected on the console. Runtime translation needs no network.

Use `i18n::t("A complete sentence with {0}.", {value})` for messages. Keep a
whole sentence in one entry so translators can reorder its arguments. Arguments
are inserted literally; file names containing `{1}` are not interpreted again.
Existing `settings.*` and `common.*` keys remain supported. New messages use
their English source text as the key.

Use `i18n::c("Label")` when an API requires `const char *`. Its result belongs
to the catalog and remains valid across language changes, until `init()` runs
again. Load the catalog once, before starting workers. Translate static tables
at their point of use so reopening a screen respects the selected language.
Never translate paths, protocol fields, format identifiers, log identifiers,
file names, or metadata supplied by the user. Do not branch on translated text.

`screens::plural` selects complete count phrases from the catalog. The supported
languages use singular/plural entries; French also uses singular for zero.
Chinese and Japanese entries can use the same phrase for both counts.

`source/core/remote_page.cpp` includes a small dictionary of web messages and
server-rendered HTML markers. Add web messages to that dictionary as well as the
catalog. Escape text inserted into HTML, and escape `<` in the JSON dictionary
so translations cannot end a script element.

Run `python3 scripts/check-i18n.py` and `make -C tests check`. CI checks the seven
language sets, placeholder counts, source keys, and direct untranslated UI
entry points. Unit tests cover fallback, literal arguments, stable pointers,
counts, and localized/escaped Receive HTML. These checks supplement a manual
audit; they do not prove every possible screen or string is covered.

Translations include machine-assisted drafts with reviewed common terminology.
Catalog completeness does not certify linguistic quality. Native review and
testing on a physical console are still useful, especially for long dialogs.
